**RobinRun** 是一个**通用型常驻自动化 Harness**：以项目为单位组建多智能体团队，触发器驱动、全天候自动运转——智能体只在被触发时启动，状态沉淀在文件里，人随时可以插话和接管。

## RobinRun 是什么

把一个长期运转的项目（监控、运营、开发协作……任何领域）交给一个智能体团队：

- **主智能体**是项目总管，负责方向、规划、分工、进度与验收；
- 按需编制**常驻 worker**（开发、运营、分析等），各自拥有独立会话与状态文件；
- **触发器**（定时 / webhook / 脚本）在事件发生时自动唤醒对应的智能体；
- 你在群聊式对话区里与所有智能体协作，随时插话、随时打断，重大事项由主智能体上报给你决策。

| 概念 | 一句话说明 |
| --- | --- |
| 项目（工作空间） | 一个主体 / 一个长期目标一个项目，数据、智能体编制、触发器相互隔离 |
| 主智能体（master） | 项目总管：方向、规划、分工、进度、验收全部兜底 |
| worker | 常驻执行智能体（开发、运营等），独立会话 + 独立状态文件 |
| subagent | 任意智能体临时拉起的帮手，任务结束即销毁 |
| 触发器 | 定时 / 本地 webhook / 脚本三类事件源，事件自动唤醒智能体 |
| 运营面板 | 需求、审批、反馈与项目进度账本 |

## 与常见 Agent Harness 的区别

| | 常见单智能体 Harness | RobinRun |
| --- | --- | --- |
| 组织形态 | 单智能体，一次处理一个会话 | 项目制 + 三层编制：master → 常驻 worker → 临时 subagent |
| 驱动方式 | 以人发起对话为主 | 事件驱动：触发器自动唤醒对应智能体，人可随时介入 |
| 生命周期 | 会话结束工作即停止 | 项目持续运转；智能体仅被触发时启动，无常驻 LLM 循环 |
| 状态沉淀 | 依赖会话上下文 | 状态文件与知识库落盘，是跨会话唯一可信状态 |
| 协作模型 | —— | 群聊形态：worker 之间不直连、经主智能体转达；用户可插话、可打断 |
| 使用形态 | CLI / 编辑器插件为主 | 桌面应用，所有项目共用一个窗口 |

## 核心功能

- **项目制工作空间**：一个窗口承载所有项目；左中右三栏——智能体树与触发器文件夹 / 群聊对话区（按发送者分块）/ 信息面板（网页预览、文件目录等）。
- **多智能体协作**：worker 与主智能体同构（独立会话、可冷恢复）；任务传递走请求-响应式 ContactAgent，续聊显式寻址；用户可在任何会话打断、插话。
- **触发器系统**：
  - **事件源**：定时（cron / interval）、本地 webhook（端口 + path/token 双校验）、脚本（常驻采集进程，或定时跑一趟即退）；
  - **投递路由**：direct / fixed / dispatcher 三档——dispatcher 按话题聚类把事件路由给对应会话；同一来源事件去抖合并，绑定会话忙时先攒后投，一源一会话续用上下文；
  - **稳定运行**：脚本统一走 emit 上报契约，连续异常自动熔断暂停并通知，恢复后自动清零重启，崩溃自动退避重启；
  - **托管浏览器**：引擎托管 chromium 供脚本使用，登录态加密存档；登录失效时自动唤起有头窗口让你重新登录，关窗即重新存档；
  - **开箱即用**：桌面版内置 Python 运行时，脚本触发器无需自配环境。
- **运营面板**：需求、审批、反馈与项目进度账本（主智能体独占维护，原位更新、只呈现有效最终态）。
- **LLM 自由配置**：自选模型提供商与 API key，不绑定单一厂商。
- **文件化状态与知识库**：智能体状态尽量落文件，按主题拆分 + 索引目录，读取先查索引、只取相关子文件；经验条目以追加为主，新旧冲突标注取代关系而不覆盖。
- **上下文压缩**：超过软阈值开始引导收尾并支持主动压缩，到达硬顶无条件强制压缩，长会话成本可控。
- **扩展生态**：MCP、插件市场、技能（skills）扩展智能体能力。
- **自动更新**：Windows 与 Linux AppImage 内置更新器；mac 版暂为手动下载升级。

## 典型应用场景

任何「长期运转、事件驱动、多角色分工」的领域都适用，编制与触发器完全按需组建。例如：

- **信息监控与采集**：定时/常驻脚本盯网页与数据源 → 事件按话题聚类路由 → 分析 worker 归档进知识库 → 重要变化唤醒主智能体向你汇报。
- **事件响应值守**：外部系统 webhook 告警直达 → 值守 worker 初步研判与处理 → 拿不准的升级给主智能体，由你拍板。
- **线上账号运营**：定时采集热点与评论区 → 运营 worker 起草内容与回复 → 主智能体把控节奏 → 用户反馈回流形成闭环。
- **开发协作**：需求与反馈进运营面板 → 主智能体拆解并派给开发 worker → 产出验收、进度账本留痕。

## 关键设计思想

### 什么时候用多智能体

判断标准是**职责分界**，不是并发：

- 不同职能域（开发 / 运营 / 分析……）各自需要长期驻守、持续积累自己的知识库与状态文件时，才值得设常驻 worker；
- 并行执行不需要上多智能体——多会话与临时 subagent 就能解决，一次性任务交给 subagent 即可；
- 主智能体可兼任具体职能（自我定位永远是项目总管）；推荐从「主智能体 + 开发 + 运营」的最小编制起步；
- worker 之间不直连，一切沟通经主智能体转达，保持信息枢纽与决策权清晰。

### 触发器的触发场景

按事件形态选事件源：

- **纯时间驱动**（每天几点、每隔多久）→ 定时来源（cron / interval）；
- **周期检查一趟就完** → 脚本的定时执行模式：到点 spawn 一趟采集 → 上报 → 退出，不占常驻配额；
- **需要持续监听、长连接采集** → 脚本常驻模式；同一职责域的多类事件合进一个常驻脚本，不为分而分、不为合而合；
- **外部系统推送** → 本地 webhook。

事件多且话题杂时开启 dispatcher 路由：话题聚类、按话题分发，压缩即淘汰已完结话题，不维护路由表文件。

### 仅触发时启动

不存在常驻运行的 LLM 循环。智能体仅被事件触发时启动：独立触发开启新会话，同一触发源续用同一会话延续上下文。token 只花在被触发的工作上。

### 文件即状态

会话只承载过程，**文件是跨会话唯一可信状态**。知识库分而治之：一个总览文件 + 索引目录 + 多个主题子文件，读取时先查索引、只取相关子文件，不整库加载；经验条目以追加为主，禁止无约束改写既有内容。

### 全自动但有闸门

- 你可以随时打断、插话、接管任何智能体的会话；
- 触发器需要决策时唤醒主智能体，重大事项由主智能体上报给你确认，不擅自拍板。

## 安装

从 [GitHub Releases](https://github.com/yuwei369/RobinRun/releases) 下载对应平台的安装包（最新版本以 Releases 页为准）。当前安装包均未做代码签名，首次安装需要按各平台说明放行一次。

### Windows 11（win-x64）

1. 下载 `.exe` 安装程序并双击运行；
2. 若弹出「**智能应用控制已阻止此应用**」，需要先关闭智能应用控制：打开 **设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 智能应用控制设置**，选择「**关**」；
3. 重新运行安装程序完成安装。

> 注意：智能应用控制一旦关闭，通常需要重装/重置 Windows 才能重新开启，请自行权衡。若弹出的是 SmartScreen「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」即可。正式签名后此步骤可去除。

### macOS（Apple Silicon / Intel）

1. 下载对应架构的 `.dmg`，打开后把 RobinRun 拖入「应用程序」；
2. 当前 mac 包未签名公证，首次打开需在终端移除隔离属性后再启动：

```bash
sudo xattr -rd com.apple.quarantine /Applications/RobinRun.app
```

> mac 版自动更新暂不可用，新版本请在 Releases 页手动下载。

### Linux（x64）

- **AppImage**：`chmod +x RobinRun-*.AppImage` 后直接运行；
- **deb / rpm / pacman 包**：按发行版常规方式安装。

### 首次启动

1. 创建一个项目（一个窗口可承载多个项目，冷启动自动打开最近项目）；
2. 在设置中配置模型提供商（API 地址与 key）；
3. 与主智能体对话，让它组建 worker 编制、配置触发器，项目开始运转。

所有数据保存在本机 `~/.robinrun` 目录。

## 从源码构建

环境：Git、Node.js **≥ 24**、pnpm **10.33.2**（版本以 [mise.toml](mise.toml) 为准）。

```bash
pnpm bootstrap     # 安装依赖 + 准备桌面运行资源 + 全量构建
pnpm dev:desktop   # 启动桌面端开发环境
pnpm typecheck     # 类型检查
pnpm lint          # 代码检查
```
